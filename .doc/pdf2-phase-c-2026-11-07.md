# PDF 2.0 Phase C — Associated Files — Implementation Report

**Date:** 2026-11-07
**Scope:** PDF 2.0 support, Phase C of `pdf2-support-plan-2026-11-07.md`

## What Was Implemented

Reader — **`src/document/associated_files.rs`** (new, ~500 lines incl. tests):
- `AfRelationship` enum — 7 ISO 32000-2 Table 43 values; unknown names → `Unspecified` + `log::warn!` (never error, R1).
- `FileSpec` — `/F` (ASCII), `/UF` (Unicode, *required* in PDF 2.0 files), `/Desc`; `display_name()` prefers `/UF`.
- `EmbeddedFile` + `EmbeddedFileParams` — `/Size`, `/ModDate`, `/CreationDate`, `/CheckSum` (Table 44).
- `parse_af_entry(doc, /AF obj)` — array (or single unarrayed spec); entries failing to resolve to FileSpec dicts skip + warn.
- `catalog_associated_files(doc, catalog_dict)` / `page_associated_files(doc, page_dict)`.
- `parse_embedded_file` — `/EF → F` (fallback `UF`); indirect streams route through `PdfDocument::get_stream_data` (encryption + filters applied); inline streams decode via `decode_with_doc`. Decode failure degrades to `embedded = None`, metadata preserved.
- pdf-name hex-escape decoding: `/Subtype /text#2Fplain` → `text/plain`.

API — `src/document/catalog.rs`: `Catalog::associated_files(doc) -> Vec<FileSpec>`; `src/document/mod.rs` declares the module.

Writer — `src/writer/document.rs`:
- `PdfWriter::add_associated_file(relationship, name, data) -> Result<u32>` — FlateDecode `/EmbeddedFile` stream (`/Params /Size` = uncompressed length) + `/Type /Filespec` with `/F` (ASCII-sanitized fallback) + `/UF` (PDFDocEncoding bytes when ASCII; UTF-16BE + BOM otherwise) + `/AFRelationship` + `/EF → F → stream`. Callers reference the returned id in the catalog `/AF` array.
- `/Params` dates intentionally omitted for deterministic output (round-trips/goldens) — editor layer adds when needed.

Fixed regression introduced by Phase A's header gate:
- `parser::version::detect_version` now also accepts `%FDF-m.n` (FDF shares the PDF object grammar — `forms/fdf.rs` round-trip tests broke when `%PDF-`-only detection rejected FDF exports). `%PDF-` marker wins when both are present.

## Design Decisions

- **Breakage-tolerant reader**: malformed `/AF` payloads (wrong types, unresolvable refs) degrade per the plan's dual-version policy ("never fail document open", R1) — spec/quality parity with our graceful-unknown-operator stance.
- **`get_stream_data` routing for embedded streams**: reuses the encrypted-stream + double-checked-decode path rather than a parallel implementation — Associated Files inside AES-256 docs decrypt for free.
- **`/UF` as text string, not PDF name**: §7.11.3 Table 42 defines file name as a *text string* (PDFDocEncoding or UTF-16BE); the writer emits UTF-16BE+BOM only when the name is non-ASCII so bytes stay identical to what 1.x readers saw for ASCII names.
- **ASCII `/F` fallback** (`é` → `_`): 1.x extractors reading `/F` get a stable name; the Unicode one is preserved via `/UF` + `display_name()`.
- **Fixture builder asserts sequential object numbers** — the first crafted fixture silently had a numbering gap (5→7 with a free slot 6), which the builder caught; renumbered to 1..7.

## Test Coverage

`document::associated_files` (9): doc-level AF chain (name/relationship/description/embedded data/params), page-level AF, `/UF` UTF-16BE preference via `display_name`, no-AF → empty for both levels, filespec without `/EF` → unembedded, broken `/EF` target keeps metadata, unknown relationship degrades, wrong-typed `/AF` entry skipped, single unarrayed `/AF` spec.

`writer::document` (2): full writer→parser round-trip (flate stream decodes to original bytes, size + names + relationship preserved); Unicode name round-trip (`résumé.txt` survives `/UF`, ascii fallback `r_sum_.txt` in `/F`).

`parser::version` (3): `%FDF-1.4`/`%FDF-1.2` accepted; `%PDF-` wins over `%FDF-`.

## Known Limitations / Follow-up

- `/AF` array-chain resolution depth is bounded by `PdfDocument::resolve`'s existing recursion guard.
- Writer PDF 2.0 opt-in (header `%PDF-2.0`, `/Version 2.0`, always-`/UF`) is Phase E — `PdfWriter` still emits `%PDF-1.7`; `add_associated_file` is 2.0-shaped but version header-neutral.
- `/CheckSum` exposed as hex string from the dict; no recomputation/validation of MD5 yet (spec conformance is passive).
- Incremental-update preservation of foreign `/AF` entries (don't drop unknown dicts on save) — noted in the plan as explicit follow-up.
