## Design Decisions

- **Writer-generated fixtures, not hand-crafted bytes:** they serve double duty — parser fixtures *and* writer golden samples. Generator is committed so fixtures stay reproducible/diffable.
- **Placeholder signature bytes in the LTV fixture** are loud (all-zero opaque block) and documented in fixture header, example doc comment, and test module — prevents any future consumer mistaking the fixture for a valid CMS sample. Real signed fixtures need the write-side signing path.
- **Fixture naming keeps plan names** (`pdf2-signed-ltv.pdf`), with allowed exceptions documented; adherence over aesthetics for cross-referencing with the plan.
- **No new fixture for future-version tolerance** (`%PDF-2.7` warn+parse): already covered by Phase A crafted-bytes tests; a binary fixture would freeze a warning-path that is deliberately non-normative.

## Known Limitations / Follow-up

- `pdf2-encrypted-r6.pdf` — blocked on writer-side R6 encryption (plan §7 last bullet).
- OCSP/CRL cryptographic validation, VRI-hash verification, PAdES profiles — separate phase (plan §7).
- Writer emits no `/DSS`; incremental updates to LTV documents must preserve/extend the existing store — same foreign-dict-preservation follow-up flagged in Phase C for `/AF`.
