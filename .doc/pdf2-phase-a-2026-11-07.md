# PDF 2.0 Phase A — Version Model + Header Tolerance — Implementation Report

**Date:** 2026-11-07
**Scope:** PDF 2.0 support, Phase A of `pdf2-support-plan-2026-11-07.md`

## What Was Implemented

- **`src/parser/version.rs`** (new, ~330 lines incl. tests):
  - `PdfVersion` enum: `V1_0 … V1_7`, `V2_0`, `Unknown(u8, u8)`.
  - `from_parts(m,n)` → enum (unknown pairs stay `Unknown`, never error).
  - `major()/minor()/to_string()/is_pdf2_or_later()/is_pdf1()` accessors; Unknown versions `>= 2.0` count as PDF 2.0-or-later for downstream encryption policy.
  - `detect_version(data) -> Result<PdfVersion>` — scans the **first 1024 bytes** (spec §7.2 scan window, not just offset 0 — real files sometimes start the header after a binary-comment line) for `%PDF-m.n`.
- **`src/error.rs`**: new `PdfError::Header { offset }` variant (R7: carries byte offset).
- **`src/parser/objects.rs`**:
  - `PdfDocument` gains `pub version: PdfVersion` field + `version()` accessor (R11 doc comment).
  - `parse()` (non-crypto path) and `parse_with_password()` both call `detect_version` **before** XRef loading — cheap fail-fast, and the version is available to Phase B's encryption policy gates.
  - Integration tests: v1.4 / v2.0 / future-2.7 headers parse through full `PdfDocument::parse`; missing header → `Err(Header { offset: 0 })`.
- `src/parser/mod.rs` re-exports the module.

## Design Decisions

- **Future-version tolerance (spec §7.2)**: unknown versions produce `log::warn!` + successful parse, per the dual-version policy table in the plan. Only corrupt header *bytes* (e.g. `%PDF-AB`) or absence of the marker in the whole window is `Err`.
- **`Unknown` carries its `(major, minor)`** rather than collapsing to a unit variant, so downstream gates (encryption policy, `is_pdf2_or_later`) can compare against a threshold instead of treating "unknown" as "oldest" or "newest".
- **Falsy-header policy**: when `%PDF-` is found but digits are malformed, the error offset points at the *marker*, not at 0 — callers can show the exact corrupt bytes.
- **Version parsed in both parse paths**, not delegated — `parse_with_password` doesn't call `parse()`, so both branches must gate (mirrors existing structure, avoids touching crypto init order).
- Fixed a latent dead-code bug: `MINIMAL_PDF`'s `startxref` declared 190 but the `xref` keyword sits at 186 — the fixture had never been parsed (was `#[allow(dead_code)]`); corrected to 186.

- RC4-forbidden-in-PDF-2.0 encryption policy (`version.is_pdf2_or_later()` gate in `crypto/handler.rs`) — Phase B.
- Fixtures `pdf2-*.pdf` and `REBUILD_PLAN.md` pointer update — Phase F.
- **Version bump to 0.2.0**: `PdfError::Header` is a new exhaustive-match case (R10, pre-1.0 minor bump) — CHANGELOG updated with breaking note.
